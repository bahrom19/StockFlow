### HIGH — Sales Report `summary.payments` uses gross cash for overpayments — **FIXED** ✅

**Evidence (pre-fix, live):**
- Overpayment sale: total 900, CASH tendered 1800, change 900.
- Sales Report returned `payments.cash = 1800` (gross tendered) while `summary.revenue = 1400` (net).
- `1800 + 0 + 0 + 300 + 200 = 2300 ≠ 1400` — the required invariant **Cash + Card + QR + Bank + Wallet = Total Sales** was violated for overpayment sales in the Sales Report only.

**Root cause:** `reports.service.ts` aggregated raw `payment.amount` per method without netting `changeAmount` from the cash bucket — while `sales.service.ts` correctly posts `cashSalesNet = cash − change` to the CashShift. So the CashShift, X/Z reports, and accounting were correct; only the Sales Report breakdown diverged.

**Fix (applied, reporting layer only):** in `reports.service.ts`, each sale's `changeAmount` is now subtracted from its CASH contribution during aggregation, mirroring `sales.service.ts` (`cashTotal += cashTendered − changeAmount`). Other methods unchanged. No changes to Sales, CashShift, GL, Journal, FIFO, Costing, or Inventory.

**Files changed:** `backend/src/modules/reports/services/reports.service.ts` (fix) · `backend/src/modules/reports/services/reports.service.spec.ts` (+5 regression tests).

**Regression tests added:** exact payment · overpayment · mixed payment · mixed payment with overpayment · refund after overpayment — each asserts `cash == net` and `sum(payments) == revenue`.

**Control (proves isolation):** a fresh company with a **non-overpayment** mixed sale (CASH 600 + CARD 400 + QR 200 = 1200 exact) returns `payments` sum == revenue == 1200 ✅. The invariant now holds everywhere.

**Post-fix verification:** independent live audit on :3100 = **51/51 PASS** — the previously-failing invariant check (`payments sum == revenue == 1400`, with cash reported as 900 net) now passes.

**Severity post-fix: resolved.**
