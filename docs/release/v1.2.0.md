## 1. Release Summary

StockFlow v1.2.0 delivers the commercial-grade payment analytics layer and completes the
enterprise POS on top of the frozen v1.1.1 accounting core. No backend API changes were
made in this release beyond the additive v1.2.0-phase1 payment allocation; accounting,
GL, journal, costing, FIFO and average-cost behavior are identical to v1.1.1.

## 2. What's New

### Backend (v1.2.0-phase1, already deployed)
- Additive migration: `qrSales`, `bankTransferSales`, `mobileWalletSales` on `CashShift`.
- Explicit per-method payment allocation: `CASH | CARD | QR | BANK_TRANSFER | MOBILE_WALLET`.
- Refund allocation reverses the exact original payment composition.
- Reports (Cash Shift, X/Z Report, Dashboard, Sales Report) expose every method independently.
- Reporting-layer fix: cash contribution = tendered − change, so the invariant
  `Cash + Card + QR + Bank + Wallet = Total Sales` holds everywhere.

### Flutter
- **Payment Analytics Dashboard**: cards per method (amount, % revenue, tx count, avg ticket),
  pie (distribution), line (daily trend), bar (comparison) charts; adaptive layout.
- **Payment Details**: table with search/sort/pagination, CSV export (existing) + **PDF export** (new).
- **Enterprise POS**: two-panel cashier workspace, catalog/cart panels, barcode workflow,
  held sales, customer picker, cash shift panel, professional receipt print/PDF services.
- **Cash Shift / X / Z UI**: shows all five payment buckets with live invariant.

### Infrastructure
- **Phase 3 web deployment automation**: `Web Deploy` GitHub Actions workflow
  (analyze → test → build web → deploy via Railway CLI), nginx SPA service
  (immutable hashed assets, entrypoint revalidation), `web-deploy/` Docker assets.

## 5. Known Limitations / Follow-ups

- **Flutter Web static host pending**: the Web Deploy pipeline is fully automated and green,

  `RAILWAY_WEB_SERVICE_ID` secrets are provisioned (see DEPLOYMENT_GUIDE §11). API backend
  remains live and untouched.
