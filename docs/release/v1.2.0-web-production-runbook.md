## 2. The one missing piece

The Railway **Static Service has not been provisioned**. Only one GitHub Secret is required
(`RAILWAY_TOKEN`); the service is targeted **by name** `stockflow-web`, so no service-id secret is
needed. Currently the deploy job correctly skips (build/test still run green):

```
gh secret list  → (empty)
RAILWAY_TOKEN   → missing
```

Provisioning requires a Railway account token, which is **not available in this environment**.
Complete the steps below (≈10 minutes) and the pipeline deploys automatically on the next push.

## 3. Step-by-step provisioning

### Step 3.1 — Create a Railway project token (recommended)

A **project token** is scoped to the StockFlow project, so the CLI can resolve the
`stockflow-web` service name in `--ci` mode without any extra config.

1. Open the **StockFlow project** in Railway → **Settings → Tokens**.
2. Click **Generate Token** → name it `stockflow-web-deploy`.
3. Copy the token (it is shown **only once**).

> Account-level tokens (https://railway.com/account/tokens) also work, but a
> project token is the safer, CI-recommended choice — least privilege, and the
> CLI binds the service name to exactly this project.

### Step 3.2 — Create the Static Service in Railway

1. Open the **StockFlow project** in Railway: https://railway.com/project
2. Click **+ New** → **Empty Service** (a blank container — we will deploy the nginx Dockerfile via the CLI).
3. After creation, open the service → **Settings** tab.
4. Set **Root Directory** to `web-deploy` (the folder holding `Dockerfile`, `nginx.conf`, `railway.json`).
5. **Name the service `stockflow-web`** (Settings → Service Name). The pipeline deploys **by this name** — no Service ID is required.

### Step 3.3 — Add the GitHub Secret

Only one secret is needed — the account token:

```bash
gh secret set RAILWAY_TOKEN -b "railway_<token from 3.1>"
```

Verify:

```bash
gh secret list
# RAILWAY_TOKEN  Updated <date>
```

### Step 3.4 — Trigger the deployment

```bash
git commit --allow-empty -m "ci: activate web deploy" --allow-empty
git push origin main
```

GitHub Actions **Web Deploy** now runs the full pipeline; the final `deploy` job executes (service
name comes from the workflow `env`):

```bash
cd web-deploy
npx --yes @railway/cli@latest up --service stockflow-web --ci
```

### Step 3.5 — Get the public URL

```bash
railway domain        # or in UI: service → Settings → Networking → Generate Domain
```

Expected public URL pattern: `https://stockflow-web.up.railway.app`

## 4. Post-deploy verification

## 5. Exact CLI reference (all commands)

```bash
# one-time
gh secret set RAILWAY_TOKEN -b "<token>"
gh secret list

# trigger
git commit --allow-empty -m "ci: activate web deploy"
git push origin main

# watch
gh run list --branch main --workflow 'Web Deploy'

# deploy-equivalent (manual fallback, same command the CI runs)
cd web-deploy
npx --yes @railway/cli@latest up --service stockflow-web --ci

# public URL
npx --yes @railway/cli@latest domain --service stockflow-web
```

## 6. Rollback

- **App code:** push a revert; the pipeline redeploys the previous green commit automatically.
- **Hosting:** Railway keeps prior deployments — open the service → **Deployments** → select previous → **Redeploy**.
