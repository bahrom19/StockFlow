# Dashboard v3.2 — Концепция «Финансовая панель» (Hero Cash Drawer + Today's Revenue)

**Статус:** концепция для согласования. Реализация НЕ начата.
**Правило:** только presentation-layer, только существующие эндпоинты, ноль изменений backend.

---

## 1. Зачем

Сейчас два главных финансовых блока страницы живут отдельно:
- **Cash Drawer Hero** (Этап 1) — «сколько денег в кассе и сходится ли она?»
- **KPI «Today's Revenue»** — «сколько заработали сегодня?»

Для владельца это один и тот же вопрос: **«как дела с деньгами прямо сейчас?»**. Два разрозненных блока заставляют глаза прыгать. Объединение даёт единый финансовый «кокпит» в верхней части Dashboard, отвечающий на 3 вопроса за один взгляд:
1. Сколько денег в кассе? (drawer)
2. Сколько заработали? (revenue)
3. Сходится ли касса и куда идут деньги? (difference + breakdown)

**Ключевые решения:**
- Одна карточка с общим заголовком, статусом смены и «Updated X sec ago» (уже реализовано в hero — переезжает на уровень панели).
- Три внутренние колонки: **Cash Drawer | Revenue + прогресс месяца | Средний чек** (это и есть текущие «Top KPI», объединённые в один блок).
- Нижняя полоса — детализация: мини-бухгалтерия кассы (4 колонки из hero) + платежи по методам (из Today's Payments).
- Цветовая индикация состояния (Этап 2) сохраняется: зелёный/красный/серый на всю панель.

## 3. Источники данных (уже проверены в backend)

| Блок | Данные | Эндпоинт |
|---|---|---|
| Cash Drawer | `expectedClosing, difference, cashIn, cashSales, cashOut, openedAt, status` | `GET /reports/cash-shifts` (X-report через cashShiftProvider) |
| Revenue today | `todaySales.revenue, todaySales.count` | `GET /reports/dashboard` |
| Средний чек | `todaySales.averageReceipt` | `GET /reports/dashboard` |
| Прогресс месяца | `monthSales.revenue` (+ цель — локальная настройка, Этап 2.1) | `GET /reports/dashboard` |
| Платежи | `payments{cash,card,qr,bankTransfer,mobileWallet}` | `GET /reports/sales` (сегодня) или todayPaymentsProvider |

Инвариант панели: **Cash + Card + QR + Bank + Wallet == Total Sales** (гарантируется backend-агрегацией, повторяется визуально).

## 4. Иерархия и поведение

1. **Заголовок панели**: «Financial Overview» + статус смены (точка Open/Closed) + «Updated X sec ago» (живой тикер 1с).
2. **Три колонки-метрики**: касса (крупно), revenue (крупно + прогресс-бар месяца), средний чек (компактно).
3. **Полоса детализации**: кассовая бухгалтерия слева, платежи по методам справа (сейчас это нижняя строка hero + Today's Payments Card).
4. **Состояния**: loading → один общий shimmer-скелетон; нет смены → панель в режиме «No open shift» с CTA (касса скрыта, revenue/чек остаются); error → retry на всю панель.

---

## 5. Что происходит с существующими блоками

- **CashDrawerHero** — его контент становится левой колонкой панели; сам hero перестаёт быть отдельным блоком.
- **KPI «Today's Revenue»** — выезжает из KPI-ленты в центральную колонку панели; в ленте KPI остаются Today's Sales, Gross Profit, Inventory Value, (Customers → заменён в Этапе 3).
- **Today's Payments Card** — компактная версия (полоса методов) переезжает в низ панели; полноценная карточка остаётся в ряду графиков.
- **Лента KPI** — становится 4-карточной (без Revenue) или сохраняет состав — решение за владельцем.

## 6. Границы и риски

- **НЕ реализуется сейчас**: только документ. Реализация — отдельный согласованный этап.
- **Цель месяца** (прогресс-бар) требует локальной настройки владельца (UI-only) — решено в Этапе 2.1, без backend.
- **Ширина**: на 1024px три колонки панели сжимаются (FittedBox на числах); на 768px панель складывается в вертикальный стек (касса → revenue → чек → детализация).
- **Порядок блоков Dashboard вне панели** не меняется до отдельного согласования (требование владельца).
