## 2. Зоны и спецификация поведения

### 2.1 Top Alert (условный, скрыт если всё чисто)
- Виден только при ≥1 проблеме. Одна самая важная (единый приоритет):
  1. `difference ≠ 0` у открытой смены → красный, CTA «Открыть Z-отчёт»
  2. Нет открытой смены → янтарный, CTA «Открыть смену»
  3. `outOfStockProducts > 0` → красный, «N товаров закончились»
  4. `lowStockProducts > 0` → янтарный, «N товаров на исходе»
- Одна строка, severity-цвет, иконка, CTA. Всё чисто → блок отсутствует (не пустой).

### 2.2 Cash Drawer hero (#1)
- Заголовок «Ожидаемая касса» = `expectedClosing`.
- 4-колоночный мини-ряд: Внесено (`cashIn`), Наличные (`cashSales`), Безнал (card+qr+bank+wallet), Сдача (`cashOut` — для наличных выплат) — *проверить трактовку на этапе реализации*.
- Строка «Разница: 0 ✓» зелёная / красная `difference` с tooltip «ожидалось X, фактически Y».
- Нет открытой смены → карточка в нейтральном состоянии: «Смена не открыта · [Открыть смену]» (без пустых нулей).
- Loading → skeleton hero. Error → компактный retry.

### 2.3 Revenue + Progress (#2)
- Число = `todaySales.revenue` (крупный tabular, hero-акцент).
- Progress bar = `monthSales.revenue` против цели месяца (см. §7.1): заполнение, «$X из $Y · Z%».
- Тренд «▲ +18% vs вчера» из `yesterdaySales.revenue`.

### 2.4 Average Receipt (#3)
- `todaySales.averageReceipt` + тренд против вчерашнего среднего чека.
- 0 продаж → «—» + подпись «Первая продажа покажет темп» (не выглядит сломанным).

### 2.5 Money Flow (#4)
- Компактная лента из 4 строк: Sales in `+todaySales.revenue` (зелёный), Refunds `−Σ` (красный), Purchases `−purchaseTotal` (синий, пометить что это за период — см. §7.3), NET.
- NET = revenue − refunds − purchases. Цвет: зелёный/красный.
- Refunds: сумма продаж `REFUNDED + PARTIALLY_REFUNDED` за сегодня (см. §7.3).

### 2.6 Quick Actions (#5)
- Один primary «New Sale F2» + ghost-плитки (Open Shift, Add Product, New Customer, Purchase).
- Навигация на реальные роуты (уже существуют).

### 2.7 Sales Trend (#6) — главный график
- Табы: 7 дней / 30 дней / 90 дней (клиентская агрегация списка продаж, §7.4).
- Hover на столбце: «Пт 7 авг · 469 000 ₸ · 6 чеков» (требование #10).
- Сегодня — акцентный цвет; вчера/прошлые дни — приглушённый; при выборе «7 дней» пунктиром «вчера в это же время».
- Empty (0 продаж): PremiumEmptyState «📈 Продаж пока нет — проведите первую продажу» + CTA.

### 2.8 Payments donut (#7)
- Текущий виджет Today's Payments; сумму в центре (469 000 ₸), легенда с % и суммами.
- Инвариант Cash+Card+QR+Bank+Wallet = Total сохраняется визуально.

### 2.9 Top Selling (#8)
- Переключатель «По выручке / По количеству» — ресортировка того же ответа `GET /reports/products/top` (`revenue` / `quantitySold` уже есть в каждом item).
- Топ-5, rank, имя, сумма. Empty → PremiumEmptyState + CTA «Добавить товар».

### 2.10 Low Stock — список (#9)
- Не счётчик, а реальный список: имя, SKU, остаток, склад, статус-цвет (🟠 LOW / 🔴 OUT).
- Ссылка «View all N →» на Inventory.
- Источник: `GET /reports/inventory/low-stock` (уже отдаёт items списком — правка #6 дешёвая).

### 2.11 Pending PO (#11) — условная карточка
- Рендерится только при `summary.byStatus[PENDING|ORDERED] > 0` (правка #7).
- «📦 N заказов ждут приёмки →» → Purchasing screen. Нет pending → карточки нет вообще.

### 2.12 Last Sale (#10)
- Последняя COMPLETED продажа: время (`createdAt`), сумма (`total`), способ оплаты (`payments[].method`), кассир (§7.2).
- Нет продаж → PremiumEmptyState «Первая продажа появится здесь».

### 2.13 Recent Sales + AI Insights (#12)
- Остаются с прошлой версии; Recent Sales пустой → «Нет продаж сегодня · [Создать продажу]».

### 2.14 Onboarding (новая компания)
- Единый OnboardingHero (из v2) остаётся, но вместо «0 везде» показывает прогресс шагов «2 из 4»: Add products → Add customer → Open shift → First sale.

## 7. Честные оговорки по данным (важно для согласования)

### 7.1 Цель месяца для Progress Bar
В API нет поля «цель месяца». Варианты: (a) локальная настройка владельца в профиле/настройках (новая UI-настройка без backend), (b) прогресс = `monthSales.revenue` от среднего за прошлый месяц (вычисляется из `grossRevenue` — это «всё время», не месяц). Предлагаю (a) — локальная цель по умолчанию 0 (бар скрыт, пока цель не задана). Требует подтверждения.

### 7.2 Имя кассира в «Последней продаже»
`/sales` отдаёт `cashierId`, но не имя кассира (имя есть только в `/reports/cash-shifts`). План: имя из `currentUserProvider` если `cashierId == текущий пользователь`, иначе fallback «Кассир · id-суффикс». Если нужно настоящее имя любого кассира — потребуется расширение ответа sales (не backend-изменение в этой фазе).

### 7.3 Refunds и Purchases в Money Flow
- Refunds: нет поля в `/reports/dashboard`; сумма берётся из списка продаж по статусам `REFUNDED,PARTIALLY_REFUNDED` за сегодня (клиентская агрегация).
- Purchases: `purchaseTotal` в dashboard — это сумма по всем заказам (без фильтра даты). На этапе реализации проверить семантику: если это «всего», использовать как «Закупки (всего)» или подписать «Закупки за месяц». Либо взять из purchasing-отчёта. Решение зафиксировать в Этапе A.

### 7.4 График «сумма + число чеков»
Профит-отчёт отдаёт daily revenue без count. Для «сумма + N чеков» (правка #10) серия дней строится клиентски из списка продаж (уже загружается для Recent Sales): группировка по дню → revenue + count. Это допустимо до ~500 продаж/период; для больших объёмов нужен эндпоинт с агрегацией (v1.3 backlog).
