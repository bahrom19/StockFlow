# StockFlow — Known Limitations

> **Версия:** 1.0.0-RC
> **Дата:** 2026-07-30
>
> Этот документ честно перечисляет все известные ограничения системы.
> Они не будут исправлены в версии RC, но запланированы для версии 1.1.

---

## 1. Security & Auth

### 1.1 Нет смены / восстановления пароля
**Описание:** Отсутствуют endpoint'ы `forgot-password`, `reset-password`, `change-password`. Пользователь, забывший пароль, не может войти в систему.
**Обход:** Администратор создаёт нового пользователя. Храните пароли в менеджере (Bitwarden, 1Password).
**План:** v1.1

### 1.2 Rate limiting только на /auth/login
**Описание:** `@nestjs/throttler` настроен только на `POST /auth/login` (5 req/min). Остальные публичные endpoint'ы (`/auth/register`, `/auth/refresh`) не защищены от brute force.
**Влияние:** Теоретически возможны brute force атаки на refresh token и регистрацию спам-аккаунтов.
**План:** v1.1

---

## 2. Products

### 2.1 Нет проверки уникальности SKU и штрихкода
**Описание:** Можно создать несколько товаров с одинаковым SKU или штрихкодом. Поиск по SKU может вернуть несколько товаров.
**Обход:** Контролируйте уникальность SKU вручную при создании товаров.
**План:** v1.1

### 2.2 `stockQuantity` в CreateProduct игнорируется
**Описание:** Поле `stockQuantity` в форме создания товара не влияет на остатки. Остаток всегда = 0. Товар нужно ставить на склад отдельно через Goods Receipt или Stock Adjust.
**Влияние:** Путаница для новых пользователей.
**План:** v1.1 — убрать поле или реализовать начальную постановку на склад.

---

## 3. Sales

### 3.1 Чек (receipt) всегда в статусе DRAFT
**Описание:** При завершении продажи чек создаётся со статусом DRAFT и никогда не переводится в COMPLETED или PRINTED.
**Влияние:** Не влияет на печать чека, но финансовые отчёты по чекам могут быть некорректны.
**План:** v1.1

### 3.2 `softDelete` использует permission `sales:cancel`
**Описание:** DELETE endpoint на Sales использует permission `sales:cancel` вместо `sales:delete`. Невозможно дать права на удаление без прав на отмену.
**План:** v1.1

---

## 4. Purchasing

### 4.1 Goods Receipt автоматически завершается
**Описание:** Goods Receipt создаётся сразу со статусом COMPLETED без возможности предварительного просмотра и подтверждения. Нет DRAFT workflow.
**Влияние:** Нельзя отменить receipt до подтверждения. Ошибка приёма требует создания reverse операции.
**План:** v1.1

### 4.2 Finance journal error при goods receipt — silent
**Описание:** Если создание бухгалтерской проводки при приёмке товаров падает, ошибка логируется (warning), но не показывается пользователю. Складские остатки обновлены, проводки нет.
**Влияние:** Расхождение между складским и бухгалтерским учётом.
**План:** v1.1 — пробрасывать ошибку пользователю.

---

## 5. Inventory

### 5.1 Stock list без DB-пагинации
**Описание:** `GET /inventory/stock` загружает все записи в память, затем фильтрует. При 10,000+ товаров производительность деградирует.
**Обход:** Не будет проблемой для <1000 товаров.
**План:** v1.1 — добавить skip/take в репозиторий.

---

## 6. Finance

### 6.1 Нет проверки, что account принадлежит company
**Описание:** `JournalEntriesService.create()` не проверяет, что все accountId в проводке принадлежат companyId пользователя. Теоретически возможна меж-tenant проводка.
**Влияние:** Низкая вероятность (UUID), но нарушение multi-tenant.
**План:** v1.1

---

## 7. Reports

### 7.1 Нет экспорта отчётов
**Описание:** Ни один отчёт (Sales, Profit, Inventory, Dashboard) нельзя экспортировать в CSV, PDF или Excel.
**Обход:** Копирование данных вручную.
**План:** v1.1 — добавить CSV экспорт.

### 7.2 Low stock threshold hardcoded = 5
**Описание:** Порог "низкого остатка" в Dashboard отчёте = 5. Не настраивается на уровне товара или склада.
**План:** v1.1

---

## 8. Billing

### 8.1 Stripe SDK не установлен
**Описание:** Stripe провайдер реализован (mock), но `npm install stripe` не выполнено. Платежи не работают.
**Обход:** Выставлять инвойсы вручную через `POST /billing/invoices/:id/pay`.
**План:** v1.1

### 8.2 Subscription expiration не проверяется автоматически
**Описание:** Нет cron задачи для проверки истекших подписок. Trial может длиться бесконечно.
**План:** v1.1

---

## 9. RBAC

### 9.1 Нет защиты от удаления последней Admin роли
**Описание:** Можно удалить последнюю роль Admin у последнего пользователя. Компания теряет возможность управлять ролями.
**План:** v1.1

---

## 10. API & Docs

### 10.1 Нет header-based API versioning
**Описание:** Только URL prefix `api`, без версионирования (`api/v1`). При breaking changes — все клиенты сломаются.
**План:** v1.1

### 10.2 HTTP-кэширование (Redis) не используется
**Описание:** `CacheModule` и `CacheInterceptor` зарегистрированы, но ни один контроллер не использует `@CacheControl`. Кэш на 0% endpoint'ов.
**План:** v1.1

---

## 11. Infrastructure

### 11.1 Нет readiness probe
**Описание:** Docker HEALTHCHECK проверяет только `/api/health/live` (liveness). Нет `/api/health/ready`, который проверяет доступность БД и Redis.
**Влияние:** Docker может считать контейнер "здоровым", когда приложение ещё не готово к запросам.
**План:** v1.1

### 11.2 Нет Sentry / crash reporting
**Описание:** Unhandled rejections и uncaught exceptions не мониторятся внешне. Только логи на сервере.
**План:** v1.1

### 11.3 Graceful shutdown без таймаута
**Описание:** `PrismaService.onModuleDestroy()` не имеет таймаута на отключение. Если БД не отвечает — процесс может зависнуть.
**План:** v1.1

### 11.4 Нет автоматического backup
**Описание:** Отсутствует скрипт автоматического бэкапа БД. Рекомендуется настроить через Railway Backup или внешний сервис.
**План:** Перед запуском production

---

## 12. Testing

### 12.1 Нет E2E тестов
**Описание:** Ни один E2E тест (HTTP → Controller → Service → Repository → DB) не написан. Только unit-тесты с моками.
**План:** v1.1

### 12.2 Reports module — 0 тестов
**Описание:** 8 endpoint'ов отчётов полностью без тестов.
**План:** v1.1

### 12.3 Mobile integration tests не запускаются
**Описание:** `flutter_tester` отсутствует в окружении. Контрактные тесты mobile не проверяются автоматически.
**План:** v1.1
